These correspond to existing historical invoice balances.

create replacement invoices

deploy automatically

1. Add controlled reconciliation for EXISTING legacy invoices

We currently have a Reconcile Charge feature intended for a genuinely missing charge.

That is NOT appropriate here.

These invoices already exist and already carry authoritative outstanding balances.

Add a separate Admin action:

Reconcile Existing Invoice

or:

Classify Legacy Invoice

This action must attach classification/provenance to the existing invoice rather than creating another invoice.

2. Required Admin workflow

For each ambiguous historical invoice, Admin should see:

Billing period

Existing description
Current classification state

Admin then chooses:

Tuition
Boarding

Aftercare
Other recurring

Require:

reconciliation reason

Example:

Existing April 2026 school-fee invoice confirmed as Tuition.
3. Reconciliation MUST NOT change financial totals

Reconciliation must preserve:

invoice.id
amount_due
amount_paid
outstanding balance
payment history
existing allocations
due date
invoice reference

It must NOT:

create a new invoice
increase amount due
create a new payment
modify historical allocations

The purpose is only to give the existing obligation an authoritative category.

4. Persist classification safely

Inspect the current schema first.

Prefer existing metadata / invoice classification fields if available.

The reconciliation needs enough persisted evidence for:

getPayableObligations(studentId)

to safely recognize the existing invoice as Tuition/another recurring service.

Do not rely on:

current service pricing
current enrollment flags
frontend-only state

If schema is genuinely insufficient, explain the smallest additive migration required, but DO NOT RUN IT.
