1. Persistent login is not behaving as a persistent session

Current production behavior:

Parent checks Keep me signed in on this device
Parent successfully logs in
Browser is fully closed
Parent later returns to Harmony Parent Portal
Login page appears again

On desktop, Chrome may autofill the phone/password, but that is browser password-manager behavior and must not be treated as successful session restoration.

Correct remembered-session behavior is:

parent returns to Parent Portal
refresh token/session family is restored securely
parent goes directly into the authenticated Parent Portal
login form is not shown

Audit the complete production flow:

checkbox React state
request payload sent on login
whether rememberMe=true reaches the server
parent session-family creation
persistent refresh-cookie Max-Age / expiry
HttpOnly
Secure
SameSite=Lax
cookie Path
cookie Domain if used
refresh endpoint path
startup refresh request
credentials behavior
mobile Chrome behavior
redirect timing
frontend auth hydration
selected learner restoration

Add safe temporary diagnostics if necessary, but never log:

refresh tokens
cookies
passwords
hashes
session secrets

A remembered session must remain bounded by the fixed 30-day family lifetime.

Logout, password reset/change, Admin disable, replay detection, and logout-all must still revoke it.

2. Distinguish browser autofill from authentication

Tests must prove that remembered-session restoration succeeds even when:

password manager/autofill is disabled
login input fields are empty

Session restoration must come from the secure refresh session, not stored form credentials.
