Phase 2 Parent Activation, Persistent Login and Password Recovery has passed security review and is ready.

Proceed with Phase 3 — Parent Notification Centre & Automated Parent Alerts.

The objective is that parents should not have to randomly log into Harmony to discover important changes. Harmony should notify them when something meaningful happens and bring them back into the Parent Portal.

Do not implement WhatsApp API yet.
Do not implement two-way messaging yet.
Do not redesign the whole Parent Portal.
Do not deploy automatically.
Do not run migrations automatically.

1. Parent Notification Centre

Add a proper authenticated Parent Portal notification system.

Parent navigation should have a clear notification bell with unread count, for example:

Notifications 3

Add a Parent Notification page/inbox with:

title
safe summary
timestamp
read/unread state
related learner where applicable
action/deep link where appropriate

Read state must be per parent account.

Notifications must only expose information belonging to learners linked to that parent.

2. Meaningful notification events

Create Parent Portal notifications for appropriate events such as:

important school announcement published
learner marked absent
learner marked late
new graded result available
new invoice generated
important fee/balance update where appropriate
payment proof received
payment proof approved
payment proof rejected
payment rejection reason
payment applied to invoices
important parent document published

Do not generate noisy notifications for:

ordinary page views
every attendance edit during capture
every draft/admin edit
internal Admin actions that do not affect the parent

Design deduplication so the same underlying event does not create repeated notifications accidentally.

3. Email alerts

Reuse the existing Gmail API/OAuth infrastructure.

For selected high-value events, send a parent email after the underlying database change commits.

Examples:

Learner absent

Tariro was marked absent today.

Payment approved

Your payment of R1,000 has been approved and applied to Tariro's school account.

New announcement

Harmony Learning Institute has published a new announcement.

Emails should contain a clear:

View in Parent Portal

button.

Use the configured Harmony production URL and safe deep links.

Email failure must never roll back attendance, grades, payments, invoices, announcements or other school records.

Preserve:

Harmony Reply-To
existing Gmail API/OAuth transport
HTML/plain-text email format
subtle Powered by AutoM8 attribution
4. Notification preferences architecture

Prepare the architecture so future channels can include:

PORTAL
EMAIL
PUSH
future WHATSAPP

Do not implement WhatsApp now.

For the first release, Portal notifications are the durable source of truth.

Email is an additional delivery channel for important events.

5. Push notification hardening

Audit the existing browser-push functionality.

Fix:

subscription ownership
validation
unsubscribe support
stale subscriptions
cross-parent subscription risks

Add a visible Parent Portal setting to enable/disable browser notifications where appropriate.

Do not make push notification support a prerequisite for receiving portal/email notifications.

6. Payment notification workflow

Complete the currently missing payment communications.

Parent should be notified when:

payment proof is successfully submitted
payment is approved
payment is rejected
rejection reason is provided
approved amount is applied to invoices

Notifications should identify the correct learner and safe amount/status information.

Never expose internal payment/database metadata.

7. Attendance alerts

Add parent notifications for:

Absent
Late

Avoid sending duplicate alerts when staff edit/save the same attendance record repeatedly.

Attendance changes must remain staff-controlled.

Parent absence explanations are outside this phase.

8. Academic alerts

When a new graded result becomes available to a parent, allow a notification such as:

New Mathematics result available for Tariro.

Do not expose unnecessary academic details in email subject lines or push notifications.

Parent opens the authenticated portal to see full information.

9. Announcement integration

Existing announcement targeting rules must remain authoritative.

Only parents whose linked learner qualifies for the announcement may receive it.

General announcements may notify all eligible parent accounts.

Grade/class-specific announcements must respect exact learner scope.

10. Deep linking

Notification actions should bring the parent to the relevant authenticated section, for example:

Attendance
Grades
Fees
Payment Proof
Documents
Announcements

If the parent has a valid remembered session, opening the link should take them directly into the portal.

If authentication has expired, send them to login and safely return them to the intended Parent Portal section afterward.

Never trust arbitrary redirect URLs supplied by the client.

11. Security

Parent notification endpoints must:

require authenticated parent session
scope notifications to the authenticated parent
never accept another parent's ID from request input
use safe response allowlists
never expose storage information
never expose internal IDs unnecessarily
enforce learner authorization on notification deep links

Preserve Phase 1 multi-learner isolation and Phase 2 session security.
