We completed live Parent Portal testing and found several issues that must be resolved before the controlled parent rollout.

This is Phase 4.5 — Parent Portal Launch Blockers & Communication Targeting.

Do not send parent invitations.
Do not start full Phase 5 rollout.
Do not deploy automatically.
Do not run migrations automatically.

Preserve all Phase 1–4 security, authentication, notification and learner-isolation behavior.

1. Fix “Keep me signed in”

Production testing showed:

Parent checks Keep me signed in on this device
login succeeds
Parent closes the browser
reopening Harmony requires login again

Audit the real persistent-session flow end-to-end.

Check:

remember-me flag propagation
refresh-cookie creation
cookie expiry/max-age
cookie domain/path
Secure
HttpOnly
SameSite
production HTTPS behavior
browser-close persistence
refresh endpoint
startup identity restoration
whether the frontend incorrectly clears authentication when the browser closes

Do not weaken the Phase 2 security architecture.

The target behavior is:

normal login without remember-me = shorter session
remember-me = secure remembered session for up to 30 days
browser close/reopen should restore the parent session when the refresh session is still valid
logout/password reset/Admin disable must still revoke it

Add real integration tests for browser restart/session restoration where practical.

2. Fix mobile login checkbox

On mobile, the Keep me signed in control currently appears as a large black/blank box.

Replace/fix it with a clearly visible accessible checkbox or switch.

It must show:

checked state
unchecked state
readable label
large but reasonable mobile tap target
proper Harmony styling

Use the correct Harmony Learning Institute logo consistently on login and authenticated Parent Portal screens.

4. Temporarily hide Grades from Parent Portal

Grades currently returns a server error in live testing, and Harmony is not yet ready to require teachers to capture academic marks through this system.

For this rollout:

remove Grades/Academic Progress from Parent Portal navigation
do not delete academic data or backend functionality
do not remove teacher functionality
preserve it so it can be restored in a future academic phase

Dashboard must not display broken grade/result widgets while the feature is disabled.

Do not silently fix or redesign the academic workflow in this phase.

5. Fix financial source-of-truth discrepancy

This is a critical launch blocker.

Production testing for the same learner showed different financial values in Admin versus Parent Portal.

Example observed:

Admin:

Total due: R21,150
Total paid: R28,200
Outstanding: R0

Parent Portal:

Total billed: R21,150
Total paid: R14,100
Outstanding: R7,050

Audit exactly why these disagree.

Determine:

which database tables Admin uses
which tables Parent Portal uses
invoice source
payment transaction source
payment allocations
arrears/carry-forward logic
manual payment handling
bank-statement payments
proof-of-payment approvals
whether either view counts unallocated/overpayments differently

Do not cosmetically change one screen to match the other.

Establish one authoritative ledger/calculation model and make Admin and Parent Portal derive financial totals from the same source of truth.

Preserve transaction safety and payment audit history.

Add reconciliation tests proving Admin and Parent Portal return identical billed, paid and outstanding totals for the same learner.
