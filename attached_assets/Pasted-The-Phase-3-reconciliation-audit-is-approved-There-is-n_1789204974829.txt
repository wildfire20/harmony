4. Attendance notifications

Create meaningful parent notifications when a learner is marked:

Absent
Late

Prevent duplicates when staff save/edit the same attendance record repeatedly.

Example:

Tariro was marked absent today.

The notification should link safely to Attendance.

Attendance remains staff-controlled.

5. Academic notifications

When a result becomes newly available to the parent, create a notification such as:

New Mathematics result available for Tariro.

Do not expose unnecessary marks or teacher comments in email/push previews.

The full result remains inside the authenticated Parent Portal.

Prevent duplicate notifications if a teacher saves the same grade repeatedly without a meaningful publication/change event.

6. Payments

Add parent notifications for:

Payment proof successfully submitted
Payment proof approved
Payment proof rejected
Safe rejection reason
Payment applied to invoice/account
New invoice generated where appropriate

Make sure the notification identifies the correct learner and safe amount/status.

Payment email/notification failure must never roll back the underlying payment transaction.

7. Announcements

Existing audience/grade/class targeting remains authoritative.

Create Parent Portal notifications only for parents who are actually eligible to see the announcement.

General announcements can notify all eligible parents.

Grade/class announcements must respect exact linked-learner scope.

8. Documents

New parent/everyone documents should generate notifications only for parents authorized to see them.

Preserve learner/grade/class targeting.

Do not broadcast every document to all parent subscriptions.
