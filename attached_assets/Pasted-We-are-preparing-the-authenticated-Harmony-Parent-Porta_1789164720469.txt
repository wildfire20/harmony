1. Fix multi-learner isolation everywhere

The Parent Portal currently allows a parent to choose a learner, but several API endpoints still silently use the first linked learner.

the selected learner ID is explicitly provided
backend verifies that learner belongs to the authenticated parent
invalid or unauthorized learner IDs are rejected
never silently fall back to the first learner when a learner ID was supplied
zero-child accounts return a safe empty state

school documents
invoices
fees
payment proof
enrolled services

Add cross-child isolation tests proving Parent A cannot access another parent's learner and selecting Learner B never returns Learner A's information.

3. Make payment-proof approval safe

Payment approval must:

run in one database transaction
lock or conditionally update the pending proof
prevent the same proof being approved twice
apply payment allocation once
roll back everything if any step fails
be idempotent

Test concurrent Admin approval attempts.

4. Harden payment receipt uploads

Bring payment-receipt validation to the same security standard as admissions uploads:

PDF/JPEG/PNG only
size limits
magic-byte/signature validation
reject MIME/signature mismatches
reject invalid numeric amounts, infinity, excessive decimal precision, oversized notes/references and unsupported payment methods
5. Secure Parent Portal documents

Parent document APIs must return safe metadata only.

internal implementation metadata

Use an authenticated secure download/view endpoint and verify parents cannot access staff-only, unpublished, deleted, private admissions or unrelated learner documents.
