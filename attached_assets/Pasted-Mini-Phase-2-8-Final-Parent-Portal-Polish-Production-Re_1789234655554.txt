6. Investigate the refresh-cookie Path specifically

The remembered refresh cookie currently uses:

Path=/api/auth

This means the browser will not send that cookie directly to /parent/login.

Therefore verify the architecture carefully.

If /parent/login itself attempts to inspect an HttpOnly refresh cookie whose Path is /api/auth, that approach cannot work because the browser does not attach that cookie to /parent/login.

The correct startup flow may need to be:

Parent route loads
      ↓
frontend enters auth-hydration/loading state
      ↓
frontend calls an endpoint under /api/auth
      ↓
request includes credentials
      ↓
browser sends refresh cookie
      ↓
backend validates/rotates remembered session
      ↓
frontend restores parent identity
      ↓
portal renders

Investigate whether this Path mismatch explains the remaining production failure.

Do not broaden the cookie path unless necessary. Prefer calling the correct authenticated refresh endpoint.
