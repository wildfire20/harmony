ISSUE 1 — JPG/image receipt does not display inline

Parent and Admin can successfully:

upload receipt
Open receipt in another tab
Download receipt

But inline image preview fails.

Browser console shows the exact CSP failure:

Loading the image 'blob:https://www.harmonylearning.co.za/...'
violates Content Security Policy directive:

img-src 'self' data: https:

The receipt is a JPG:

IMG-20260909-WA0007.jpg

The current modal shows:

This browser could not display the receipt inline.
Use Open or Download below.

This occurs in both Parent and Admin receipt viewers.

1. Fix CSP for secure blob image previews

The application fetches the authenticated receipt as a Blob and creates:

URL.createObjectURL(blob)

This is correct for keeping the underlying receipt private.

Update Helmet/CSP so trusted browser-generated Blob URLs can render as images.

Current effective rule resembles:

img-src 'self' data: https:

Change only what is necessary so it also safely permits:

blob:

Example intended policy:

img-src 'self' data: https: blob:

Preserve the existing secure policy.

Do NOT:

use *
disable CSP
make receipt URLs public
weaken unrelated security directives

PDFs should retain the existing secure blob: frame support.

2. Correct preview renderer

Determine trusted server-side content type.

For:

image/jpeg
image/png
image/webp

render:

<img>

using the authenticated Blob URL.

For:

application/pdf

use the secure PDF inline viewer.

Keep:

Open
Download

as fallback actions for both.

Image preview must:

preserve aspect ratio
fit inside the modal
never stretch/distort
work on mobile
work on desktop
be large enough for Admin to verify the payment

Revoke object URLs with:

URL.revokeObjectURL(...)

when the modal closes or the receipt changes.

Prevent Blob URL memory leaks.

4. Parent must only be offered genuinely payable obligations

This is the core rule.

The Parent payment form must NOT build payable choices merely from:

learner enrollment flags
Service Pricing
current service configuration
a one-off fee card

A selectable payment item must correspond to a real authoritative payable obligation.

Parent payment choices must come from:

persisted invoice
+
persisted invoice line
+
positive outstanding category balance

or the equivalent authoritative one-off obligation.

Therefore:

Displayed as selectable

must mean:

Backend can actually allocate to it.

Do not let Parent select something that will inevitably fail during Admin approval.
